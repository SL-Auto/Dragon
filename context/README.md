# Context management contract

The repository is an indexed dependency graph. Start from `registry/tools.yml`, `manifests/<tool>.yml`, and the relevant phase profile in `context/profiles.yml`. Do not load complete reports, source trees, canonical rules, translations, or historical runs unless the active phase requires them.

## Loading order

1. Read the registry entry and tool manifest.
2. Read only the procedure summary or rule dependency record named by the work item.
3. Open full evidence only to verify a claim, resolve ambiguity, or update the analyzed revision.
4. Process one canonical rule and one target schema profile at a time.
5. Discard rule-level context before advancing to the next work item.

## Generated views

`manifests/`, `dependencies/`, `summaries/`, and `state/work-items.yml` are generated by `scripts/update-context-index.ps1`. `telemetry/MASTER.md` is an aggregate view whose rule counts are generated by `scripts/update-master-telemetry-rule-counts.ps1`. Do not hand-edit generated sections when the source artifact can be corrected instead.

## Context-pressure stop conditions

- Never load complete source trees for more than one tool at a time.
- Never load unrelated tools during rule generation, review, or translation.
- Never load secondary translations while refining canonical YARA-L.
- Never load all translations for a tool; use one rule and one backend profile at a time.
- Never load historical run logs outside the active discovery window without a specific evidence need.
- Prefer dependency records over reconstructing telemetry requirements from prose.
- Prefer summaries over full reports until a citation or ambiguity requires the evidence layer.

## Size budgets

- Tool manifest: at most 300 lines.
- Tool summary: at most 20 lines per procedure plus 40 structural lines.
- Rule dependency record: at most 100 lines.
- Run log: changes, blockers, validation, and follow-up only.
- Translation review: shared limitations belong in `schemas/`; record only tool/rule exceptions locally.
